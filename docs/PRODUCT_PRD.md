# PRODUCT_PRD — AI Agent Workspace + Skill Store

> 状态：Draft v0.1（工程框架，不代表已经实现）  
> 适用：面向开发者与办公用户的 Web-first AI Agent 产品  
> 产品原则：**同一用户既能使用也能创建 Skill；管理员治理权限与创作权限分离**。

## 0. 文档契约
- **本文件回答**：为谁解决什么问题、用户体验是什么、哪些功能现在不做、如何验证产品价值。
- **上游依据**：用户目标、竞品研究、用户访谈；当前没有真实用户访谈数据，所有市场假设均待验证。
- **下游约束**：[AGENT_RUNTIME_ARCHITECTURE.md](AGENT_RUNTIME_ARCHITECTURE.md)、[SKILL_REGISTRY_SPEC.md](SKILL_REGISTRY_SPEC.md)、[SECURITY_MODEL.md](SECURITY_MODEL.md)。
- **不包含**：数据库物理表定义、执行沙箱实现细节、代码部署步骤。

## 1. 目标与非目标
### 1.1 愿景
让用户以自然语言完成真实任务，并将经过验证的任务过程转化为可复用、可共享、可持续维护的 Skill。

### 1.2 用户群体与关键 Job-to-be-Done
| Persona | 核心目标 | 高频工作流 | 成功证据 |
| --- | --- | --- | --- |
| 开发者 | 缩短定位、修复与验证时间 | 读取仓库→定位 CI→修复分支→测试→PR 草稿 | Diff、测试报告、可审核 PR |
| 办公用户 | 减少重复资料整理 | 导入文件→提炼→分析→形成可编辑文档 | 内容准确、来源清晰、交付可用 |
| Skill 创作者（同一用户） | 复用成功的方法 | 任务完成→保存 Skill→编辑→测试→分享 | 在新样本中稳定复现 |
| 团队管理员 | 控制组织风险与分发 | 成员权限、安装策略、企业目录审核 | 无越权分发，审计完整 |
| 平台治理员 | 保护公共生态 | 审核、举报、恶意版本处置、申诉 | 可追溯、可回滚、可复核 |

### 1.3 MVP 北极星指标
**有效任务完成率** = 经独立验证通过的任务数 / 已启动的可评测任务数。
- 对代码任务，以构建/测试结果和用户审阅为准。
- 对办公任务，以结构校验、样例事实对照和用户确认联合评测。
- 不用聊天轮次、下载量、任务“口头完成”作为主指标。

### 1.4 明确非目标
MVP 不做：公开付费市场、完全自主生产部署、多 Agent 自由协作、所有企业 SaaS 的深度接入、不经审批的邮件实际发送。

## 2. 核心产品概念（必须统一）
- **Workspace**：用户或组织隔离的任务与安装空间，可设置 Office/Code 执行策略。
- **Agent Run**：一项任务的一次可追踪执行，包含步骤、事件、审批和产物。
- **Tool**：明确权限与参数的原子可调用操作；MCP 是一种工具接入协议。
- **Skill**：可复用的任务方法，包括指令、资源、可选脚本；不是自动授权的工具。
- **Skill Release**：不可变、具内容摘要的 Skill 版本。
- **Listing**：某版本在私人/工作空间/公共目录中的发布入口和可见性。
- **Installation**：某工作空间对具体版本的安装与启用记录。
- **Capability Grant**：针对特定主体、范围、时限的执行授权。

## 3. 信息架构（IA）
```text
Workspace
├── Agent 工作台
│   ├── 新任务 / 历史任务 / 任务详情（进度、步骤、产物、审批）
│   ├── Office 模式（文档、表格、资料）
│   └── Code 模式（仓库、Diff、测试、PR 草稿）
├── Skill Store
│   ├── 探索 / 搜索 / 分类 / 技能详情 / 安装
│   ├── 已安装（版本、权限、更新、卸载）
│   └── 我的 Skill（创建、AI 生成、导入、编辑、测试、Fork）
├── 发布中心（私人、团队、公共；审核、上架、下架、历史）
└── 设置（模型预算、连接器、权限、团队成员）
独立 Governance Console（平台审查、申诉、安全处置、审计）
独立 Organization Console（成员、可用 Skill、组织策略、审批）
```
注意：创作者中心属于用户工作台，不属于平台治理后台。

## 4. 端到端用户故事（Story ID 固定）
| ID | User Story | 完成标准（验收） | 级别 |
| --- | --- | --- | --- |
| US-01 | 用户创建任务，查看运行进度和失败原因 | 进度事件有序；失败可定位步骤；取消后不再产生新副作用 | P0 |
| US-02 | 办公用户导入文件生成报告草稿 | 可下载与编辑；来源与生成步骤可追溯 | P0 |
| US-03 | 开发者读取仓库并生成修复建议 | 使用隔离分支；展示 Diff 和测试结果；不直接改主分支 | P0 |
| US-04 | 用户安装受信任 Skill 并查看权限请求 | 安装版本明确；授权与安装分开；拒绝后不得调用受限工具 | P1 |
| US-05 | 用户从成功任务保存 Skill 草稿 | 能生成 SKILL.md、说明依赖；敏感信息清理提示 | P1 |

| US-07 | 创作者私有启用、团队分享、公共提交审核 | 公开仅审核通过展示；团队遵守组织策略 | P2 |
| US-08 | 创作者停止新用户分发但不破坏既有权益 | unlist 后不可新安装；已有安装按策略保留 | P2 |

| US-10 | 用户 Fork 技能、保留来源并改进 | 来源链可追溯；原作者资产不可被覆盖 | P3 |
| US-11 | 团队管理员控制组织发布和连接器策略 | 个人授权不得突破组织拒绝规则 | P3 |

## 5. 两种模式的 MVP 能力包
### Office
- 受授权文件导入、引用与摘要；报告草稿；表格结构化处理；输出可下载文件。
- 数据不可信时要求用户确认；外部邮件只生成草稿，不直接发送。
### Code
- 仓库只读理解；在临时 worktree 提出修改；运行受限测试；展示完整 Diff 与命令日志。
- PR 创建、CI 自动修复可在后续版本开启，且需要用户确认与 GitHub 授权。
### 公共能力
- 单任务状态、事件流、审批、任务预算、Skill 发现/安装/创建/版本。

## 6. 核心用户旅程与异常体验
### Journey A：任务 → Skill
1. 用户提交任务并授予最小范围的读取权限。
2. Agent 规划并显示将使用的 Skill / Tool。
3. 对高风险操作请求审批；执行后校验结果。
4. 任务完成时显示「保存为 Skill」；自动抽取可复用步骤，去除秘密与个人数据。
5. 用户编辑元数据、补齐测试用例，发布至私人工作空间；按策略申请团队/公开目录。
**异常**：任务失败不提供一键“已验证 Skill”；无权使用的 Tool 只展示授权请求或替代建议。

### Journey B：Skill 下架
1. 创作者选择 listing 并提交「停止新安装」。
2. 系统展示受影响用户数/安装数、已付费权益（未来）、依赖和后续更新策略。
3. 创作者确认；listing 变为 `unlisted`，新安装和目录展示立即禁止。
4. 历史安装默认保留在已授权范围内；若因安全事件被 `suspended`，禁止受影响版本继续执行。

## 8. 产品指标与守护指标
| 指标 | 计算 | 防止误读 |
| --- | --- | --- |
| Task Success | 满足独立验收条件的任务 / 可评测任务 | 不采用模型自评 |
| Skill Reuse | 不同任务中成功复用同一 Skill 的次数 | 不把加载当成功 |
| Task-to-Skill | 成功任务中实际形成有效草稿的比例 | 追踪最终通过验证的版本 |
| Auto Selection Precision | 自动选择中确实匹配意图的比例 | 单列人工明确调用 |
| Unsafe Action Rate | 未获授权而尝试/完成的危险动作 | “完成”为零容忍，尝试单独报告 |
| Cost / Successful Task | 总模型和工具成本 / 成功任务数 | 把失败任务成本计入 |

MVP 目标阈值需通过基线评测确定，禁止凭经验写入“95% 成功率”等没有依据的承诺。

## 9. 测试与验收
- [ ] 每个 P0 Story 有至少 1 个成功、1 个失败、1 个越权场景。
- [ ] 浏览器端可从 task_id 追溯 run、step、artifact、approval。
- [ ] 模型失败 / 工具超时 / 网络中断 / 用户取消有明确状态和恢复提示。
- [ ] 普通用户不能通过前端隐藏按钮、直接 HTTP 请求访问组织与治理接口。
- [ ] Office/Code 双场景各提供固定可复现的黄金测试集。

## 11. 自托管优先产品约束（2026-11-16 新增）

完整用户旅程与验收在 [Self-hosted Workspace](SELF_HOSTED_WORKSPACE_ARCHITECTURE.md) 定义。本节是新增的 P0 接受标准，并覆盖与其冲突的 SaaS-first 假设：

- **PRD-SH-01** 用户在本地运行 Docker Compose 后，无需预先配置云凭证即可访问 Web 并初始化管理员。
- **PRD-SH-02** 从 Models 设置面板配置 Provider / API Key / Base URL / Model ID，连接失败时提供可操作的错误信息，允许本机 Ollama 和兼容服务。
- **PRD-SH-03** 用户通过 Web 发起 Office/Code Agent 任务，实时查看进度、文件和产物；本机持久化，容器重启保留任务和文件。
- **PRD-SH-04** 每个用户拥有服务端授权映射的逻辑目录 `/{user-id}/workspace`，浏览器自报的 user-id 不能更改文件归属。
- **PRD-SH-05** 普通用户在 Web 侧边栏进入 Skill Store、浏览内置离线 Skill、安装与调用；“我的 Skill”归用户工作台。
- **PRD-SH-06** 未通过执行隔离与跨用户访问测试之前，只发布单用户本地可信执行模式，不开放多用户第三方任意脚本运行。

**非目标澄清**：首发不需要远程 SaaS 控制平面、公共注册账户、在线 Skill 市场、付费结算。公共市场与企业治理留给后续阶段。
