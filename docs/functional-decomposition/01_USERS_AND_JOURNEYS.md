# 01 — 用户画像、需求分解与端到端旅程

> Draft v0.4 · 假设基于技术产品访谈前的设计推演；无真实用户数据。相关：[PRD](../PRODUCT_PRD.md)、[UX](02_CLIENT_IA_AND_INTERACTIONS.md)、[验收](10_QUALITY_SECURITY_EVALS.md)。

## 1. 谁是用户？不是“消费者 / 管理员”二分法

| Persona | 关键工作 | 主要焦虑 | 初期核心行为 | 成功的证据 |
|---|---|---|---|---|
| P-A 非技术办公使用者 | 处理文件、表格、报告 | 不懂术语、担心数据泄露与错误结果 | 选任务模板、上传文件、预览确认 | 可验证的可用文件 |
| P-B 开发者 | 仓库理解、测试修复 | 破坏代码、命令失控、不可复现 | Git 仓库 → 分析 → Diff → 测试 | 真实测试与清晰 Diff |
| P-C Skill 创作者（和 A/B 是同一个人） | 把方法复用和分享 | 不知怎样写格式、修改会破坏旧版本 | 将成功任务保存 Skill、测试、发布 | 两次不同输入可复现 |
| P-D 单机部署/管理员 | 配模型、管理备份和风险 | Docker 复杂、密钥泄露、磁盘故障 | 一键启动、Web 配置、备份更新 | 健康且可恢复的实例 |
| P-E 团队空间管理员（P2） | 分享和限制能力 | 成员越权、组织数据外流 | 策略、成员、Skill 分发 | 跨用户严格隔离 |
| P-F 公共 Registry 治理者（P2+） | 安全审核、申诉、恶意包阻断 | 供应链攻击、版权和滥用 | 审核、撤销发布/执行 | 违规版本可精准处置 |

**关键推演**：P-C 不应强制转成“开发者账号”。把“我创建的 Skill”放在普通用户工作台；P-D 只管理本地系统，不能因为有 admin 角色就默认无理由查看每位用户的文件、聊天与凭证。P-F 在首发没有公共中心 Registry 时可完全不存在。

## 2. 任务语义（避免概念混淆）

`Conversation` 是长久对话线；`Run` 是其中一轮可审计执行；`Step` 是工具/模型/验证动作；`Workspace` 是持久文件上下文；`Artifact` 是执行产物；`Skill Release` 是不可变版本；`Installation` 代表“此空间允许 Pi 装载的特定版本”。

用户可能继续聊天却不继续前一次 Run；Run 失败不意味着 Conversation 已删除；取消等待中的副作用不得当成回滚已产生的副作用。

## 3. 黄金旅程 J-01：首次 Docker 启动到首个模型回复

前提：用户安装 Docker，机器能访问所选模型端点。步骤：
1. `docker compose up -d --build`；Web 首次启动向导展示服务状态、数据存储位置和模型配置入口。
2. 首次管理员初始化受一次性机制保护；实例不存在预置密码。无模型 Key 可以完成初始化。
3. 「添加连接」选择协议/供应商、输入 Base URL、Model ID、API Key；展示「连接测试」与诊断原因。
4. 测试成功才标记为 ready；模型未必支持 tool calling，需再验证工具兼容性。
5. 发起「Hello + 读工作空间文件目录」受控任务，前端按 Run 实时显示结果、完成状态和成本（若供应商返回）。
6. 刷新页面与冷重启后，聊天记录和模型连接仍存在。

异常推演：端口占用 / Docker 未准备好 / DB 未初始化 / 容器内 localhost 错误 / URL 指向不可达主机 / Key 错 / 模型不支持 tool call / 供应商断线。每种情形必须给出不同错误类型，不建议“请重试”一刀切。

## 4. 黄金旅程 J-02：Office 文件处理

- 输入：用户上传两个 CSV 或 XLSX，任务是比较差异并生成报告；原文件不可被静默改写。
- 预览：显示文件名、大小、类型、扫描结果和用户许可的工作空间目录。
- 执行：Pi 选择允许的文件读取/处理工具，输出结构化分析过程和新文件。
- 验证：检查输出文件实际存在、可被正常解析、统计校验一致；若失败显示 FAILED + 可复现原因，而非“已完成”。
- 用户：浏览器预览差异、下载、保存到工作空间指定目录，重复文件名不能静默覆盖。
- 异常：损坏文件、空表、编码异常、超大附件、断线、生成失败、用户取消；都应保留原输入并记录失败产物。

**取舍**：首发支持明确的 UTF-8 CSV/Markdown/PDF 可读内容与一个 Excel 工作流；不要把 PowerPoint、邮件发送、数据库读写同时列入 P0。

## 5. 黄金旅程 J-03：Code 分析与改动

1. 授权导入/克隆测试仓库到当前 Workspace；后端验证输入路径，禁止直接访问宿主机其它项目。
2. Pi 首发默认只读：`read`/`grep`/`find`/`ls`，生成问题诊断、测试建议。
3. 后续受控编辑：基于 Git worktree 生成 Diff，标明每个文件变化的意图。
4. 测试只能在单任务 Sandbox 中运行，记录命令、退出码、环境约束、测试是否真实跑过。
5. 通过验证后的改动仍需用户批准才能写回原仓库；推送或提交 PR 属更高风险操作。

异常：未 Git 初始化、脏工作树、子模块、LFS、依赖下载失败、并发两个 Run 修改同文件、超时。每种要明确冲突/回滚/重新验证路径。

## 6. 黄金旅程 J-04：从任务沉淀 Skill

用户完成 J-02 或 J-03 后选择「保存为 Skill」，系统：
1. 提取**工作方法**，不是把完整私人聊天、私钥、业务文件复制进公开 Skill。
2. 生成最小 `SKILL.md` + 必要支持文件；显示结构检查、触发描述、输入要求、工具依赖、风险。
3. 在可控、去隐私的 fixture 上运行两次；检查它是否能在不同输入上重复成功。
4. 创建 Draft，用户编辑、保存私有不可变 Release，安装到当前 Workspace。
5. 未来分享给其他用户时另走 Listing 与审核，不把“私人安装”视作上架。

失败：Skill 与现有同名、触发误命中、依赖缺失、脚本被拒绝、LLM 输出截断、用户删除被引用的资源。要能查看原因、回到草稿、继续编辑。

## 7. 横向功能拆解（按价值）

| 功能 ID | Job | P0 必须 | 推进理由 | 明确不做 |
|---|---|---|---|---|
| F-ONB | 从本地部署到模型可用 | ✓ | 阻断式入口 | 自动收费/公有注册 |
| F-CHAT | 多轮消息/任务进展 | ✓ | Agent 可理解性 | 无限并发任务 |
| F-FILE | 上传读取/产物交付 | ✓ | 办公最短闭环 | 任意本机全盘扫描 |
| F-CODE | 仓库问答/受控 Diff | ✓只读 | 可验证工程闭环 | 默认直接 push main |
| F-SKILL-DISC | 浏览并安装内置 Skill | ✓ | 初次复用价值 | 上千社区技能 |
| F-SKILL-CREATE | 从任务生成私人 Skill | P1 | 创作者转化 | 自动公开发布 |
| F-PUBLISH | 审核/发布/下架 | P2 | 社区增长 | 首发中央服务 |
| F-TEAM | 成员/权限/审计 | P2 | 多人可用 | P0 任意代码多租户 |

## 8. MVP 北极星不是 MAU，而是“可信成功完成”

建议指标：有效任务成功率、文件校验通过率、代码测试实际执行率、任务可恢复率、Skill 二次成功复用率；同时记录高风险操作拒绝率、未授权操作次数、每成功任务成本。不得为了提高成功率把未运行测试算成通过。

## 9. 仍未验证的需求假设

- A1：本地 Docker 配置比原生桌面安装更能满足目标开发者；需实际 3–5 名新用户装机观察验证。
- A2：多数办公用户愿意自行配置模型 Key；可后续考虑本地 Ollama 引导，但不替用户擅自下载大模型。
- A3：对创作者而言“从当前任务生成 Skill”比纯编辑器更有价值；需测观察用户是否真正复用。
- A4：内置市场足够支持初期复用；如果安装复用低，不能直接推断缺少更多技能，需要先检查 Skill 触发和任务质量。

## 10. 验收追踪

- AC-J01：无 API Key 启动成功，连通真实兼容模型并能输出；错误 Key 提供具体反馈。
- AC-J02：输入样本未改变，输出文件有效且可下载，重启仍存在。
- AC-J03：无授权不得写入主工作树，所有测试显示 PASSED/FAILED/NOT RUN。
- AC-J04：私人 Skill 可从编辑、测试到安装并跨 Run 复用；禁用立刻影响新 Run。
- AC-J06：严格跨用户 ACL + OS 隔离测试；未通过不得开放相应功能。
